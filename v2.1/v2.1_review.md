## Architectural Highlights & Wins

### 1. High-Level Facade (`SVGTranslationService`)

The introduction of `SVGTranslationService` as the singular public entry point is a massive architectural improvement.

-   **Decoupling:** It shields callers from the internal mechanics (`SVGTranslationExtractor`, `SVGTranslationInjector`, `MappingStore`, and `preparer`).
-   **Workflow Orchestration:** Standard workflows like **extract-and-inject** are unified into single method calls, while preserving standalone access if the caller desires only one phase.
-   **Robust Return Model:** Programmatic results are wrapped inside a generic `OperationResult[T]` structure containing structured `error_code`s and optional lists of `warnings`.

### 2. Standardized Configuration (`TranslationConfig`)

Replacing scattered inline arguments with an immutable dataclass-based config model enhances static safety.

-   **Immutability:** Avoids runtime bugs caused by unintended configuration mutability.
-   **Builder Pattern:** The `.with_updates(**kwargs)` helper allows callers to easily derive modified configurations dynamically.
-   **Feature Flags:** Standardizes behaviors such as language normalization, case-insensitive matches, automatically creating parent directories, and configurable switch sorting.

### 3. Fully Unified ID Management (`IdManager`)

Legacy implementations had a high risk of ID collisions during language splitting/cloning due to localized counter variables.

-   **Global Registry:** The new `IdManager` dynamically registers all existing IDs within the SVG before injection/cloning.
-   **Deterministic Lang Suffixes:** Cloned elements append system language suffixes (e.g., `-ar`) and gracefully resolve collisions with numeric suffixes (e.g., `-ar-1`), guaranteeing global uniqueness of identifiers across the document.

### 4. Modular Preparation Pipeline

SVG preparation and structural normalization before translation are now organized into sequential, modular `PreparationStep` implementations:

1. `Load`: Parses the raw XML document.
2. `NormalizeTspans`: Handles tspan structural alignments.
3. `WrapTextElements`: Wraps loose text nodes inside `<switch>` blocks, moves style definitions up to the switch level, and validates that children are strictly `<tspan>` nodes.
4. `SplitLanguages` / `Reorder` / `AssignIds`: Prepares distinct language blocks and tags missing IDs.

-   **Extensibility:** Follows the Single Responsibility Principle (SRP). New structural transformations can be cleanly introduced by adding new pipeline steps.

### 5. Structured Exception Hierarchy

A dedicated set of exceptions derived from `CopySVGTranslationError` simplifies programmatic handling of invalid inputs:

-   Errors like `SvgNestedTspanError`, `SvgTextContainsDollarError`, and `SvgNonTspanInsideTextError` use distinct `default_code` string descriptors. This is highly useful for integrating `CopySVGTranslation` into backend microservices or UI applications.
