## Critical / high-priority issues

### 1. Preparation is incomplete vs v1

Missing behaviour that v1 had:

| Missing | Impact |
|---------|--------|
| Wrap every `<text>` in a `<switch>` if needed | Injection assumes switches; files without them will be skipped |
| Move `style` from `<text>` up to `<switch>` | Styling can break |
| Reject non-tspan children inside `<text>` | Invalid structure can slip through |
| Full empty-node / invalid-id cleanup | Partial only in `AssignIds` |
| Duplicate-language detection inside a switch | Can create invalid SVGs |

`ValidateStructure` does not cover several old checks (e.g. non-tspan inside text, switch child rules).

### 2. Bugs in `service.py`

```python
# inject() documents OperationResult[etree._ElementTree]
# but InjectResult = OperationResult["InjectorData"]
```

- Return type alias does not match what `inject` actually returns (`tree`, not `InjectorData`).
- `prepare_only` returns `OperationResult.ok(data=tree)` while typed as `InjectResult` — inconsistent.
- Extractor failures put errors in `mapping.meta` instead of raising; service then treats empty mapping as `"no_translations"` and loses the real error (`File not found` / parse error).

### 3. Bugs in injection path

**`SVGTranslationInjector.__init__`**

```python
self.config = config  # can be None
```

Later: `self.config.create_parents`, `self.config.pretty_print` → **AttributeError** if `config is None`.  
Should be: `self.config = config or TranslationConfig()`.

**`TranslationApplier` + case sensitivity**

`default_texts` are often lowercased when `case_insensitive=True`, but `translations` keys come from `lookup` / original sources. Key mismatch can prevent updates/inserts from applying the right strings.

**`SwitchProcessor`**

```python
switch.existing_languages()  # result discarded
```

Harmless but dead code.

**`IdManager.allocate_clone`**

Collision suffix uses `_{idx}` while design/docs used `-{idx}`. Minor inconsistency with v1-style ids.

### 4. `AssignIds` does not use `IdManager.allocate_trsvg`

It reimplements a local counter. Risk of divergence from `IdManager` used in split-languages / injection.

### 5. Extractor error handling

```python
except FileNotFoundError:
    mapping.meta = {"error": "File not found"}
    return mapping  # empty-ish mapping, success path in service fails generically
```

Prefer raising `SvgIOError` / `SvgParseError` so the service can return a precise `error_code`.

### 6. Version / naming drift

| Item | Issue |
|------|--------|
| `__version__ = "2.0.1"` | Folder is v2.1; align version |
| Legacy `inject` → `inject_file_tree` | OK if intentional; document the rename |
| `to_json` vs design `to_dict` | Fine, but keep one name everywhere |
| `InjectorData` still in `result.py` | Mostly unused by the new service path |

### 7. Type / API inconsistencies

- `pretty_print: bool | None = None` in config, but `tree.write(..., pretty_print=self.config.pretty_print)` may get `None`.
- `OperationResult` / `InjectResult` / actual return values disagree.
- `TranslationMapping.from_any` fallback logic is hard to read:

  ```python
  new=dict(data.get("new", data if "new" not in data else {})),
  ```
