## Common Error Messages

### SvgStructureException

The `SvgStructureException` class indicates structural problems in the SVG file that prevent translation processing. Each exception includes a `code` attribute identifying the specific issue and an `extra` attribute with additional context.

| Error Code | Description | Extra Info | Resolution |
| --- | --- | --- | --- |
| `structure-error-multiple-text-same-lang` | Multiple `<text>` elements with the same `systemLanguage` in a `<switch>` | List of duplicate language codes | Remove duplicate translations; each language should appear once per `<switch>` |
| `structure-error-css-too-complex` | SVG contains `<style>` elements with CSS selectors | Empty list | Remove or simplify CSS; use inline `style` attributes instead |
| `structure-error-invalid-node-id` | Element has an ID containing invalid characters | Invalid ID string | Rename IDs to use only alphanumeric characters, hyphens, and underscores |
| `structure-error-text-contains-dollar` | Text content contains `$` character | Text containing `$` | Remove or escape `$` characters in text content |

## SVG Compatibility

### Supported SVG Features

The translation system supports SVG 1.1 features commonly used in multilingual graphics:

| Feature | Support Level | Notes |
| --- | --- | --- |
| `<text>` elements | Full | Primary translatable content |
| `<tspan>` children (non-nested) | Full | Text segments within `<text>` |
| `<switch>` blocks | Full | Language switching mechanism |
| `systemLanguage` attribute | Full | Language code specification |
| Inline `style` attributes | Full | Preserved during translation |
| `id` attributes | Full | Required for text elements; auto-generated if missing |

### Performance Benchmarks

Approximate processing times on modern hardware (4-core CPU, 8GB RAM):

| Operation | Small SVG(~50 KB, 20 texts) | Medium SVG(~500 KB, 200 texts) | Large SVG(~5 MB, 2000 texts) |
| --- | --- | --- | --- |
| `extract()` | <0.1s | 0.2-0.5s | 2-5s |
| `inject()` (10 languages) | <0.1s | 0.3-0.7s | 3-8s |
| `make_translation_ready()` | <0.1s | 0.2-0.4s | 1-3s |
| `start_injects()` (100 files) | 5-10s | 40-80s | 5-10 min |

**Bottlenecks:**

1. **XML parsing:** Dominates for files >1 MB (use lxml's fast parser, already default)
2. **Text normalization:** O(n) where n = number of text elements
3. **ID collision detection:** O(n²) worst case; optimized with set lookups in `generate_unique_id()`
4. **File I/O:** Writing large SVGs to disk; use SSD storage when possible

## Frequently Asked Questions

### Why do I get "structure-error-multiple-text-same-lang"?

This occurs when a `<switch>` block contains multiple `<text>` elements with the same `systemLanguage` value. SVG's language fallback mechanism expects exactly one translation per language.

**Resolution:** Consolidate duplicate translations into a single `<text>` element or remove duplicates.

### Can I translate SVGs that use <tref> elements?

No. The `<tref>` element was deprecated in SVG 1.1 and removed from SVG 2. Modern SVG renderers do not support it. Convert `<tref>` references to standard `<text>` elements before processing.

### What happens if overwrite=True and the translation already exists?

The existing translation text is replaced with the new translation from the mappings. The original `<text>` element's attributes and structure are preserved; only the text content changes.

### How do I handle files with both nested tspans and other structural issues?

### Does the system preserve SVG formatting and whitespace?

By default, yes. When `pretty_print=False` (the default), the output SVG maintains the original formatting. Set `pretty_print=True` to reformat with indentation, though this may change whitespace-sensitive rendering.

### Can I use relative paths or must I use absolute paths?

Both work. The system accepts string paths, `Path` objects, or path-like objects. Using `pathlib.Path` is recommended for cross-platform compatibility:
