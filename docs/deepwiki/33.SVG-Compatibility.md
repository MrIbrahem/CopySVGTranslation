## Supported SVG Features

CopySVGTranslation is designed to work with multilingual SVG files that follow specific structural conventions. The system supports:

| Feature | Support Level | Notes |
| --- | --- | --- |
| `<text>` elements | Full | Primary target for translation |
| `<tspan>` elements | Full | Used for inline text segments |
| `<switch>` elements | Full | Used for language variants |
| `systemLanguage` attribute | Full | Language detection and targeting |
| Basic attributes (id, x, y, style) | Full | Preserved during processing |
| Unicode text content | Full | All character sets supported |
| Simple `<a>` anchor elements | Partial | See limitations below |

The system expects SVG text content to be structured with `<switch>` blocks containing multiple `<text>` elements, each with a `systemLanguage` attribute indicating the language variant.

### Complex CSS Selectors

**Status:** Not supported

SVG files containing `<style>` tags with CSS selectors (class selectors, ID selectors, etc.) are not supported because they can create unpredictable interactions with the ID generation system used during translation injection.

**Unsupported structure:**

```

```

**Exception raised:** `SvgStructureException` with code `"structure-error-css-too-complex"`

**Workaround:** Convert CSS styles to inline `style` attributes on individual elements before processing.

**Sources:** [tests/inject/test_inject2.py L89](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/tests/inject/test_inject2.py#L89-L89)

### Invalid Node IDs

**Status:** Not supported

Element IDs containing special characters like pipes (`|`) or other characters that could interfere with ID generation are rejected.

**Unsupported structure:**

```

```

**Exception raised:** `SvgStructureException` with code `"structure-error-invalid-node-id"` with the invalid ID in the `extra` field

**Workaround:** Rename IDs to use only alphanumeric characters, hyphens, and underscores.

**Sources:** [tests/inject/test_inject2.py L90](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/tests/inject/test_inject2.py#L90-L90)

### Dollar Signs in Text Content

**Status:** Not supported

Text content containing dollar signs (`$`) is rejected to avoid conflicts with template variable systems or other text processing tools.

**Unsupported structure:**

```

```

**Exception raised:** `SvgStructureException` with code `"structure-error-text-contains-dollar"` with the text content in the `extra` field

**Workaround:** Replace dollar signs with a different symbol or textual representation (e.g., "USD 3" or "3 dollars").

**Sources:** [tests/inject/test_inject2.py L91](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/tests/inject/test_inject2.py#L91-L91)

### Multiple Text Elements with Same Language

**Status:** Not supported

Within a single `<switch>` block, only one `<text>` element per language is allowed. Having multiple text elements with the same `systemLanguage` value creates ambiguity.

**Unsupported structure:**

```

```

**Exception raised:** `SvgStructureException` with code `"structure-error-multiple-text-same-lang"` with the list of duplicate language codes in the `extra` field

**Workaround:** Consolidate multiple text elements for the same language into a single element, or use separate `<switch>` blocks.

**Sources:** [tests/inject/test_inject2.py L71-L81](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/tests/inject/test_inject2.py#L71-L81)

### <tref> Elements

**Status:** Not supported

The deprecated `<tref>` element (used for referencing text content from other elements) is not supported. This element was removed from the SVG 2 specification.

**Workaround:** Replace `<tref>` elements with direct text content or `<use>` elements with appropriate cloning.

**Sources:** Mentioned in page purpose but not implemented in codebase

The `fix_nested_file()` function automatically transforms nested structures into supported sibling structures while preserving all attributes, styling, and text content order.

## Exception Reference

All SVG compatibility exceptions inherit from `SvgStructureException`, which provides structured error information:

```

```

**Exception attributes:**

* `code`: Machine-readable error code string
* `extra`: Additional context (element IDs, text content, etc.)
* String representation includes both code and extra information

**Common error codes:**

* `"structure-error-nested-tspans-not-supported"`: Nested tspan detected
* `"structure-error-css-too-complex"`: CSS selectors in style tag
* `"structure-error-invalid-node-id"`: Invalid characters in ID
* `"structure-error-text-contains-dollar"`: Dollar sign in text
* `"structure-error-multiple-text-same-lang"`: Duplicate language in switch

## Best Practices

1. **Validate before processing**: Always run `make_translation_ready()` to validate structure before translation
2. **Fix nested elements first**: Apply `fix_nested_file()` to files with nested structures before attempting injection
3. **Use inline styles**: Avoid `<style>` tags with selectors; use inline `style` attributes instead
4. **Clean IDs**: Ensure element IDs contain only alphanumeric characters, hyphens, and underscores
5. **Avoid special characters**: Remove dollar signs from text content before processing
6. **One language per text element**: Within each `<switch>`, ensure each language appears only once
