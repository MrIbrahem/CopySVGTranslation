## Overview

The CopySVGTranslation project is structured as a modern Python package using `pyproject.toml` for configuration, `hatchling` as the build backend, and GitHub Actions for CI/CD automation. The package requires Python 3.10+ and has minimal runtime dependencies.

**Development Stack:**

| Component | Tool | Version Requirement |
| --- | --- | --- |
| Build Backend | Hatchling | >=1.17 |
| Testing Framework | pytest | (latest) |
| XML Processing | lxml | >=4.9 |
| Code Formatter | black | line-length=100 |
| Import Sorter | isort | profile=black |
| CI/CD | GitHub Actions | - |

Sources: [pyproject.toml L1-L35](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/pyproject.toml#L1-L35)

## CI/CD Workflows

The project uses GitHub Actions for automated testing and publishing.

### Workflow Architecture

```

```

**CI/CD Pipeline Diagram: Two workflows handle testing on PRs and publishing on releases**

### Test Automation Workflow

The `pytest.yaml` workflow runs on every pull request:

**Workflow Configuration:**

* **Trigger**: Pull requests to any branch
* **Runner**: `ubuntu-latest`
* **Python Version**: 3.10
* **Caching**: pip dependencies cached by `requirements.txt` hash

**Steps:**

1. Checkout code using `actions/checkout@v6`
2. Setup Python 3.10 using `actions/setup-python@v6`
3. Cache pip packages using `actions/cache@v5` with key `${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}`
4. Install pytest: `pip install pytest`
5. Install dependencies: `pip install -r requirements.txt`
6. Run tests: `pytest`

Sources: [.github/workflows/pytest.yaml L1-L35](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/.github/workflows/pytest.yaml#L1-L35)

### Publishing Workflow

The `python-publish.yml` workflow publishes to PyPI when a GitHub release is created:

**Workflow Structure:**

| Job | Purpose | Key Steps |
| --- | --- | --- |
| `release-build` | Build distributions | Install `build`, run `python -m build`, upload artifacts |
| `pypi-publish` | Publish to PyPI | Download artifacts, publish using trusted publishing |

**Key Features:**

* **Trusted Publishing**: Uses `id-token: write` permission for secure PyPI authentication
* **Environment**: Uses `pypi` environment with deployment protections
* **Artifact Handling**: Distributions uploaded/downloaded as `release-dists` artifact
* **PyPI Action**: `pypa/gh-action-pypi-publish@release/v1` handles publishing

**Security Configuration:**

* Permissions scoped to specific needs (`contents: read`, `id-token: write`)
* Dedicated deployment environment with protections recommended
* No API tokens required (uses trusted publishing)

Sources: [.github/workflows/python-publish.yml L1-L63](https://github.com/MrIbrahem/CopySVGTranslation/blob/307ef348/.github/workflows/python-publish.yml#L1-L63)

### CI/CD Best Practices

The workflows implement several best practices:

1. **Dependency Caching**: Speeds up builds by caching pip packages
2. **Separate Jobs**: Build and publish split into separate jobs for better control
3. **Artifact Management**: Build artifacts passed between jobs via upload/download
4. **Trusted Publishing**: More secure than API token-based authentication
5. **Version Consistency**: Python 3.10 in tests matches minimum required version
6. **Minimal Permissions**: Each job has only required permissions
